# 官方资料基线盘点

本文记录目前已盘点到的官方示例特征，用作后续复制最小参考基线时的索引。官方资料保持在 `local_refs/official_package`，仅可只读查阅；本轮未复制任何官方源码。

## PCIe 入口

- 已盘点到 AFC03 与 IMX415 相关的 PCIe 教程和 V4L2 示例。
- 该 PCIe V4L2 示例偏向固定长度原始图像传输；驱动中可见 RGB24、每像素 3 字节及固定帧大小等硬编码假设。
- 它可作为板卡启动、PCIe/DMA、驱动和数据通路的参考基线，但不能直接视为赛题 3 的最终协议。
- 若 FPGA 输出可变长度 JPEG 帧，Linux 侧需要自行明确 DMA 接收、帧边界、长度管理与解码流程，不能直接套用固定长度原始帧的示例。

## MIPI 入口

- 已盘点到 IMX415 MIPI 教程及虚拟传感器相关示例。
- 示例中存在固定的 YUYV、1920×1080、60 FPS、4 Lane 等配置。
- MIPI 可作为备选图像输入链路；是否可用及其格式、分辨率、帧率、lane 配置仍须与 FPGA 设计和 RK3576 平台能力一起验证。

## V4L2 入口

- PCIe 示例以 V4L2 形式暴露视频采集路径，是验证设备枚举、缓冲区和用户态采集的参考入口。
- V4L2 节点号不能硬编码：先前示例使用过 `/dev/video73` 和 `/dev/video22`，但实际节点号必须在目标板上运行时确认。
- 最终方案需先定义数据格式和帧协议，再决定是否适配为标准 V4L2 视频节点，或以专用 PCIe/DMA 用户态接口承接数据。

## RKNN 入口

- 已盘点的 RKNN 示例使用 Python 与 OpenCV，曾以 `/dev/video73`、1280×720、30 FPS 取流，并只使用一个 NPU Core。
- 该示例可作为模型加载、预处理、RKNN 推理与结果展示的参考入口。
- 设备节点、输入分辨率、帧率及 NPU Core 使用策略都不是固定约束，需随最终采集链路和性能预算调整。

## 当前结论

PCIe 暂定为主链路、MIPI 为备选，仍是候选方案。后续应在双方接口明确后，分别从官方资料中复制最小必要参考代码到正式工程，并记录来源与改动。
