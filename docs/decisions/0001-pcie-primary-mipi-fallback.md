# 0001：PCIe 主链路、MIPI 备选链路

- 状态：候选决策（proposed）
- 日期：2026-09-13
- 决策方：Linux 与 FPGA 双方共同确认

## 候选决定

暂定 PCIe 作为 FPGA 与 RK3576 间的主链路，MIPI 作为备选链路。

## 选择理由

- PCIe 更适合承接 FPGA 输出并由 Linux 侧进行 DMA 接收、帧边界管理、JPEG 解码和 RKNN 推理的分层处理。
- 现有官方资料包含 PCIe 与 V4L2 参考入口，可用于后续建立最小可验证基线。
- MIPI 仍保留为备选，可在 FPGA 输出形式、平台支持或联调约束更适合传感器式视频输入时采用。

## 尚未确认的问题

- PCIe 设备 ID、BAR 布局、DMA 方向、队列数量与中断模型。
- 传输原始图像还是可变长度 JPEG，以及帧头、长度、序号、时间戳和校验定义。
- 图像格式、分辨率、帧率及端到端带宽、缓存和延迟预算。
- Linux 侧采用 V4L2 适配、专用字符设备，还是其他用户态数据接口。
- MIPI 的 lane 数、时序、格式和 RK3576 接收端支持情况。
- 错误、复位、超时和恢复流程。

## 确认要求

本决策尚未生效。Linux 与 FPGA 负责人必须共同确认接口合同、实现边界和验证计划后，才能将状态改为已接受或改用其他链路。
