# 融合工程功能与参数

以下是同一比特流的配置范围。帧率是传感器名义档位，不代表任意画面、质量和主机负载下的实际退休帧率。
ISP、预处理、JPEG、DDR 控制器和 PCIe 传输共用，没有为 4K 或 HDR 再复制整套处理链。

| 输入与档位 | JPEG 处理 | RAW10 |
| --- | --- | --- |
| 单目 1920×1080 SDR60 | 彩色、灰度、高斯、HE、去雾；保留原单目车道/多尺度用途 | 支持 |
| 双目 1920×1080 SDR30/40/45/48 | 彩色、灰度、高斯、HE、去雾及原合法组合；两眼共用配置，历史按眼隔离 | 支持 |
| 单/双目 1920×1080 HDR，原约30fps目标 | 平衡/旧兼容融合、四档 Tone、渐进高光保护、原合法预处理组合；双像素 Tone 和 DDR 预取保留 | 不适用；RAW 使用原 SDR 独立会话 |
| 单目 3840×2160 SDR15/20 | 彩色、灰度、高斯、HE及组合，新增同一套手动 RGB 白平衡 | 支持；绕过 ISP/JPEG |

4K 不开放 HDR、去雾、车道；双目不开放单目车道/多尺度。45/48 是探索档。
既有模型显示高熵图案可超出共享 JPEG 的持续服务能力，新增流水优化不改变这一限制。
本轮 3840×4 验证行宽和数值，480×32 验证产品退休，不能折算为满幅持续 FPS。

运行前按冷态协议选择眼数、JPEG/RAW、速率和几何。APP/C2H 启动后锁定；停止与换会话须完成承诺排空。
传感器直接输出30fps的双目档，其协商 divisor 仍可读为2，实际捕获分频为1，不二次减半。
高帧率通过传感器 HMAX/VMAX 配方切换，FPGA 的处理时钟保持原值。

| 运行时控制 | 合同 |
| --- | --- |
| JPEG | Q1–100、最小Q、明确帧预算、自适应质量开关、restart MCU间隔 |
| HDR 运动与配对 | 原 motion base/shift、delta/wait/age 合法范围；保持帧身份、过期与退休保护 |
| HDR 画质 | 4档 Tone：平衡、旧版、明亮、高光；2档融合：平衡、旧兼容 |
| ISP | 两眼共用的 RGB 白平衡，手动每通道1–1023，Q8中256为1倍；适用于SDR/HDR JPEG，包括4K |

HDR 比例仍固定16:1（ratio_log2=4），黑位50/50、资格掩码15。相机任意曝光/增益、任意I²C、
高斯核、HE强度和自定义去雾 LUT 均不是本版新增旋钮；这些是来源工程已明确排除的范围。
配置通过原32字 CFG/schema2事务完整回读并等待 APPLIED，质量字段由显式能力位和版本识别。

新 SDK 兼容原 HD/UHD 的旧配置。旧 rate_r3 SDK 可用于融合 HD 的全零新增字段，
但其4K能力字做精确比较，会拒绝新4K能力字，必须随本工程升级SDK。
UART使用 DJ/v4，兼容解码旧DJ/v1–v3。业务 AJPGv4/ARAWv1 保持。
