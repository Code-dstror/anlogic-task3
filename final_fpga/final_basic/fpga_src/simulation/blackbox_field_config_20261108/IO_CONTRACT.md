# CAMERA_RAW CFG and sensor-start qualification

Contract clarifications retained from the first short runs: `PROFILE=1` is the
compiled MONO base. With runtime stereo enabled, BAR COMPILED_PROFILE is 2 and
processing capabilities are 0x0f, not the parameter superset 0x3f. New-work
admission requires both `source_ready` and `!pause_new_jobs`; PREPARE may keep
source_ready high while pause prohibits new work. Original FAIL logs are retained.

This handoff defines public interfaces for two independent short simulations. Use the repository's `docs/pcie_protocol_v1.json` and `docs/s01_config_transaction.md` as the BAR wire oracle. The field incident used seed92 at `81404aec1727e16f3df7424a74c5f960ad3d6683`. Its 13th request left CFG BUSY after CAM1 reported configuration failure. The fixture may inject one corresponding fault through a public pin or port. Model observations do not identify the physical cause in the field.

Clock USER and PIX continuously at independent periods, e.g. 8 ns and 10 ns. Assert both active-low resets at start for multiple edges of each. Once both are released, capture and return the real BOOT request through the PIX `m_config_*` / `s_config_ack_*` handshake, then poll `SESSION_READY`. A remote model returns the exact 1184-bit offered tuple, with `ok=1` unless the case calls for a negative remote ACK. Hold a valid request or response and its fields until its own rising-edge valid/ready handshake. BAR addresses are user-page relative byte offsets, naturally aligned with `write_strobes=4'hf`; hold each write for one USER sampling edge, sample its response with the write offer, and read by pulsing `read_valid` with the corresponding offset and waiting for `read_response_valid`. Never equate a transport response with an actual accepted sensor frame.

- During PREPARE, no new jobs may be admitted while `pipeline_idle=0`. READY is still BUSY and retains ownership. Provide `pipeline_idle=1` to represent drained old work before expecting READY. COMMIT uses the same request sequence and session. A delayed digital ACK must keep BUSY and ACTIVE/epoch unchanged even if the fixture pulses `frame_accept`. This pulse is an adversarial check, outside legal admission until `source_ready`.
- Positive digital ACK alone leaves the prior ACTIVE/epoch until an actual legal `frame_accept` pulse in PIX with `pipeline_idle=1`. `frame_sequence` is its actual 32-bit SOURCE sequence, including legal zero. For HDR the pulse represents the qualified LONG frame boundary from the necessary running eyes. Check matching SESSION, response sequence, ACTIVE tuple, epoch increment, and published first sequence in USER. Use the public schema2 recipe (SDR product0, dehaze enable bit1 for the predecessor; HDR product2, enables0, ratio4, black50/50, motion64/3, qualification15, delta50 ms, wait100 ms, age1 s for the target) with COLOR, Q75, minQ1, flags/budget/restart zero. Optional simpler legacy COLOR is valid for the first positive control.
- `i_apply_source_fault` is a PIX-domain held level from the required physical sensor running the newly selected profile. It denotes terminal configuration/identity failure, never training in progress or a rejected pair. After a matching positive application ACK, it must retire the owned COMMIT as `ERROR` with `CFG_ERROR=RESET (6)`, clear `BUSY` and `READY`, leave `APPLIED=0`, preserve the prior ACTIVE tuple and epoch, and inhibit further source admission. A same-edge `frame_accept` has lower priority than the fault. A terminal fault does not authorize dropping other work. A fresh coordinated reset and BOOT permit another legal first transaction. No same-session automatic retry is part of this contract.
- Minimal tests are a legal first SDR/dehaze transaction through USER APPLIED, a held drain/digital ACK before HDR, and both a legal HDR APPLIED and an HDR failure in separate sessions or transactions. For the failure, hold the fault after the HDR digital ACK with no accepted frame. Reuse the same assertions for a bounded seed92 run where available. The old interface lacks the fault port and parameter, so omit both only when compiling the frozen seed92 variant and compare at the same public deadline. A second injection where a frame is offered on the fault edge proves the priority. Prove fresh reset/BOOT recovery with one real CFG terminal.

## CAM1 frontend and I²C pins

`sdr_camera_raw_frontend` is the actual CAM1 frontend with a deliberately digital PHY pad boundary. Production profile uses defaults except `SDR_RATE_CONTROL_ENABLE=1` and `EVENT_FIFO_DEPTH=512`; `WIDTH=1920, HEIGHT=1080, FIRST_ROW=16, FIRST_GROUP=1, RUNTIME_GAIN_ENABLE=1`. For this bounded control test, override `CONFIG_WAIT_CYCLES=8`, `SDR_WAKE_CYCLES=24`, `I2C_HALF_PERIOD=6`, `SILENCE_CYCLES=12500000`, `HDR_WARMUP_PAIRS=8`, `HDR_I2C_HALF_PERIOD=7`, `HDR_RESET_HOLD_CYCLES=8`, `HDR_RELEASE_WAIT_CYCLES=12`, `HDR_REGULATOR_WAIT_CYCLES=24`. No full-size image is generated. Production timings correspond to SYS25 at 40 ns with 10/10/25 ms SDR waits, 10/30/24 ms HDR waits and 125 SYS25 cycles per SCL half-period.

Use continuous independent clocks e.g. `i_cfg_clk` 40 ns, `i_pixel_clk` 8 ns, `i_ref_clk` 8 ns, `i_sensor_clk` 41.667 ns, `i_hdr_mclk` 37.037 ns. Assert `i_reset_n=0` with all clocks running, then release while `i_clock_locked=1`. Set `i_mode_quiet=1` only while old activity is drained. Set `i_sdr_30_request=1` for a dual SDR30 predecessor. Observe the actual sensor reset and I²C for a runtime request. Model an open-drain `tri1 cam_sda`; ACK by driving low on the ninth SCL bit, release after that bit. Four bytes are written MSB first per register: `34`, address high, address low, value. SDR has 203 writes, HDR has 139; both finish with standby cancel `3000=00`, a wake interval and master release `3002=00`. `o_config_done` only rises after the final successful write. NACK stops that recipe and must yield held `o_config_error=1` with `o_config_done=0` and no HDR stable. Start with a legal boot, switch the requested profile only after the modeled old drain, and demonstrate legal application before or after a fresh reset.

The opaque digital pad boundary takes `mipi_clk_hs_rx_p` as WORD clock (e.g. 11 ns period); no packet data is supplied by `mipi_data_hs_p=0`. The real watchdog lowers `o_phy_ready` after bounded loss of that clock. To model a training interruption, ACK the new HDR recipe, wait for both `o_config_done` and `o_phy_ready`, stop the WORD clock until `o_phy_ready` drops and a receive-fault pulse is seen, then restart. The loss is before any qualified pair/established source. It may report `o_receive_fault` but must allow PHY and HDR qualification to resume while `o_config_error` stays zero. Inject public `i_hdr_pair_event` as one-PIX-edge pulses at least 20 SYS25 cycles apart. The fixture models externally validated pairs, not MIPI pixel correctness. `i_hdr_pair_ok=0` restarts the consecutive-good count; only eight consecutive good pairs permit `o_hdr_stable`. After at least one qualified pair, a PHY loss is terminal for this source cohort and must invalidate done/stable with error. The pair qualifier is reset on the existing per-mode/cohort reset. A terminal I²C NACK and configuration clock-lock loss also remain terminal without automatic retry. Permanent source identity loss and pair-event transport overflow remain failures during warmup. For the training baseline, `o_config_error` at the early PHY interruption is the expected seed92 counterexample; the post-fix expectation derives from the startup contract.
