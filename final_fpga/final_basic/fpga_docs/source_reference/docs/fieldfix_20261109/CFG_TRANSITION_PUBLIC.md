# Public CFG transition black-box contract

Test author must not read RTL, prior TB/runner implementation, vendor models or internal hierarchy. Public ABI is `docs/pcie_protocol_v1.json` in this R2 project; it may be read. Opaque source lists/compilation/hashes are allowed. Test actual `mono_config_service_v2` BAR→native command FIFO→PIX owner→native response FIFO→BAR ACTIVE publication. External capture/DFI owner is modeled only through its public request/whole-ACK interface. Do not claim this model verifies physical sensor/DDR.

Legal parameters: PROFILE=1, MAX_WIDTH=1920, MAX_HEIGHT=1080, REMOTE_CONFIG_ENABLE=1, EXT_WIDTH=1024, EXT_STRIPS=4, EXT_COMBINATIONS=0, EXT_SUPPORTED=8'h3c, V2_SUPPORTED_MODES=3'b101, V2_SUPPORTED_ENABLES=6'h3f, LIVE_GRAY_FIXED_ENABLE=0, LIVE_BASIC_MODES_ENABLE=1, COMPACT_EMPTY_EXTENSION_ENABLE=0, COMPACT_STAGE2_EXTENSION_ENABLE=1, LANE_GAUSSIAN_ONLY=1, CFG_DIAG_ENABLE=0, STEREO_CAPABLE=1, APPLY_SOURCE_FAULT_ENABLE=1. Same constants as supported production feature set. Use two asynchronous free running USER/PIX clocks (e.g. 8ns/10ns); async low reset then ordinary clocks release. i_stereo_mode=1 for dual mode tests,0 for mono control.

Full public parameter/port declarations are in `CFG_PORTS.txt` alongside this contract; named output connections can omit optional diagnostics to permit unchanged baseline compilation. `write_valid/read_valid` are one-cycle USER offers; write_strobes=4'hf. Sample write_response at offer edge, OK0/error2. read_response_valid is a response pulse, potentially delayed for RAM words; await it rather than assuming one-cycle latency. BAR addresses and commands/status/extension layouts must come from protocol JSON, no private engine words needed. Source/session identity and ACTIVE are stable until successful operation or reset. Do not use live DUT output as oracle for target configuration values.

Cold BOOT begins automatically after streams/RAM initialize. Service emits m_config_valid with a full1184-bit tuple; hold ready finitely if desired. At its real handshake capture the tuple, perform modeled full drain, then offer an exact unchanged s_config_ack_data with s_config_ack_ok=1 and hold valid until ready. Negative echo is valid with ok0. This acknowledgement certifies old capture+DFI processing are drained and new tuple accepted; it is NOT a synthetic frame. BOOT completes without a picture and publishes SESSION_READY/epoch0/COLOR75. Config tuple fields: request seq[31:0], session[63:32], mode[65:64], quality[72:66], adaptive73, minimum[80:74], frame budget[105:81], restart[121:106], reserved[127:122], target epoch[159:128], schema extension[1183:160]. For positive transitions verify outgoing tuple exactly against requested fields and old epoch+1.

The host must declare CFG_HOST_CAPABILITIES(0x274) bit0=1 before PREPARE, as required by the public ABI. PREPARE_EXT snapshots all32 extension words and scalar request fields. While old pipeline_idle=0 it must remain paused and cannot issue READY or new config; once old pipeline_idle=1 it may publish READY. COMMIT only after matching READY uses the same request/session. Until exact positive whole ACK, no new source_ready or APPLIED. Wrong ACK identity must not authorize anything; follow with correct ACK and check recovery. After ACK, pause releases so new camera frames can start. For stored dual capture, NEW frame_accept is a real accepted CAM0 SOF of the new tuple and can coexist with pipeline_idle=0 because CAM1/new processing is already busy. That legitimate event must publish APPLIED and target epoch without waiting for new work to drain. This does not waive PREPARE/full remote drain. No frame_accept: keep waiting, no invented positive terminal. i_apply_source_fault in eligible wait produces ERROR_RESET6 and leaves old public ACTIVE, including if fault coincides with frame_accept. STOP is outside this module.
