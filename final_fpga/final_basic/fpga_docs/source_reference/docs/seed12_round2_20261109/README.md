## 共用生命周期中的两个边界

[原始证据复核](EVIDENCE.md)说明两类现象需要分开：

1. **未成功切入HDR**：两轮分别第19/21笔，whole ACK与target epoch已前进，CAM1写完配方却不稳定，没有新RAW准入。配置ACK仅证明数字配置完成，不等于传感器已有合格曝光组。接收器发布从SHORT开始时，孤立、不可信或组号0的SHORT不可能等到对应LONG，旧逻辑却把它永久留在FIFO头；这会卡住后续合法组和APPLIED。`492c5384`已用旧源/候选同刺激、真实I²C/CSI/FIFO/双眼warmup链复现并修复，本轮完整保留。[启动修复与黑盒](../seed12fix_20261109/README.md)
2. **已成功进入HDR但少接作业**：四路准入每路约30.3/s，双眼job总计约50.4/s；BEGIN负答复约等于每个缺失pair两次。已接job、JPEG结果、writer ACK、USER descriptor/retire在同窗总量只差0–1。主要缺口在接job之前，不支持将它归为RK显示丢帧。两bank、同组整体拒收、共享串行服务和相位都可能参与；秒级采样不能唯一证明具体bank满时刻或排除瞬时DDR/host反压。

更深层的共同点是**阶段完成条件不可混用**：配置ACK、实际合格首帧、输入RAW归还、JPEG写完、主机退休不是同一事件。先前4a08ae35已分离旧工作排空和新流水APPLIED，并修正纯弃帧维护影响drain；此次保留这些保护。没有通过提前APPLIED、扩大超时、减少稳定对数、强行清故障、提前释放仍被借用的bank或重编SOURCE序号解决表象。

## 本轮新增的读端修正

现有两只队列各深512组RAW10，原cursor在空队列/字节进度精确追平时仅发155个16B字，即496组。这个非16拍对齐的chunk制造额外短burst，当前DDR仲裁与cursor逐burst停等，增加了共享服务开销。

改为160字，即2560B/512组；沿用原空队列信用、共享decoder、≤16拍INCR、4KiB边界、末字KEEP和取消排空协议。授权后最大未解码字节差2560，小于4096，原低12bit进度比较仍可精确证明零欠账；没有第513组。已出队数据由原有保持寄存器拥有，队列释放的存储位置可安全复用。没有新增FIFO、ERAM、DSP、CDC、业务流水或接口位宽。只有cursor常量/边界改变，reader文件更新容量证明注释。

按1920×1080固定地址范围枚举，每HDR作业读请求由21,718降为20,250，减少1,468次（6.76%）；传输字节、RAW14数值和运动检测均保持。**这不是整个系统提速6.76%的承诺，更不能据此宣称已达到30/30。** 真实DDR延迟、JPEG和两bank截止条件还要由新bit验证。
