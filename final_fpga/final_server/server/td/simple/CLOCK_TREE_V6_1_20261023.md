## 原因与修复

已取回当日约14点回传的HDR/JPEG四个物理种子（1/11/71/88）的原始Clock Tree，
每份535字节，仅4个时钟组、0个pin、0个clock节点，确实是摘要。固定源为
`SOURCE_COMMIT`，不能用另一个源的人工GUI报告补作本轮证据。

原命令缺少详细树和负载展开选项。TD 6.2.3.210850原生批处理支持：

```tcl
report_clock_summary -clocks [get_clocks *] -levels 1000000 -expand_buckets -file clock_tree.txt
```

`-levels`指定树展开深度，`-expand_buckets`展开负载桶中的各个pin。
这些选项未列入本仓库SWUG105的report_clock_summary条目，但已由实际TD执行验证。
深度0/1/2会截断小工程；使用较大正值避免较小的固定截断。该数字与线程预算无关。
不需要图形界面、模拟点击、Qt offscreen或额外安装Xvfb。

新任务在自己的原生 `controller-reports/clock_tree.txt` 自动生成详细XML，包含输入、
缓冲与全局/局部网络、负载pin以及TD输出的快慢角延迟。现有其他报告及原生流程保持。
不在重开DB后重复执行曾导致工具崩溃的额外Check Timing。

清单记录实际pin/clock/latency数量、展开的物理负载、声明的逻辑端点、缺失组、
未展开负载桶和最大pin深度。仅摘要为 `SUMMARY_ONLY`，缺组/未展开等为
`TRUNCATED_TOPOLOGY`，格式异常为 `UNRECOGNIZED_FORMAT`；这些均使报告清单为PARTIAL。
完整原生树为 `FULL_TOPOLOGY`，不表示时序通过。
原生逻辑端点计数含别名等，与物理pin数不一定相等，不能强制两者相等来判定完整性。
